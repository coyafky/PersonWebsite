模块 4.5 · Next.js 登场

从「浏览器现画」到「预渲染成真实 HTML」

纯 React 的三个尴尬其实是同一个病根，Next.js 用预渲染一招治。

纯 React（Vite 打包）

空壳 index.html + 一个大 JS → 浏览器跑完 JS 才现画
① 直接访问 /text-lab → 404（服务器上没这文件）
② 网速慢 → 访客先看一片白屏
③ 爬虫不跑 JS → 拿到空壳 → SEO 差

Next.js 预渲染

build 时把每页画成真实 HTML 文件放服务器 → 访客一来就拿到成品
① /text-lab 真有文件 → 不 404
② 内容已在 HTML 里 → 不白屏、首屏快
③ 爬虫直接读到内容 → SEO 友好

文件夹 = 路由（约定优于配置）

app/page.jsx→/
app/text-lab/page.jsx→/text-lab
加新页 = 新建文件夹，不用注册路由；跳转用 <Link>。

"use client" 开关

不写（默认）＝服务端组件：build 时画成 HTML 就完，快、利于 SEO
写"use client"＝客户端组件：除 HTML 再多送一份 JS 让它交互
客户端组件也会预渲染，只是额外在浏览器再跑一遍。
build 后 .next/server/app/ 下真有 index.html 和 text-lab.html——404 的病根除了；怎么部署是 4.6 的事。
