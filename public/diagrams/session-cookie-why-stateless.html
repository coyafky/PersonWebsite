无状态 → 会话：cookie 带 session_id

HTTP 处理完就把这一轮全忘了；解法不是改 HTTP，而是让浏览器每次自动带一个编号。
第 1 次请求服务器不认识
发新 UUID 纸条
→
处理完服务器把这一轮
状态全扔掉
→
第 2 次请求浏览器自动带
Cookie: session_id=…
→
认出来了WHERE session_id=?
只给这个人的历史

cookie vs session：一个工具，一个概念

session「认定」——把散落请求认成同一个人（一段关系）
cookie「机制/工具」——浏览器自动存、自动带的小纸条

cookie 里装的就是 session_id；跨源带它要两头点头：后端 allow_credentials=True + 前端 credentials:"include"。

两种「记忆」解法，同一件事

Web 会话状态存服务器，每次只带一个 id（32 字符）
大模型 API状态存客户端，每次把整段 messages 重发

所以上下文窗口=messages 长度上限；对话越长越贵——每轮都在为整段历史重新付费。

会话 ≠ 认证。它只认得出「这是同一个浏览器」，认不出「你到底是谁」——清掉 cookie 就当你是新访客。登录/密码/OAuth 是在会话地基上再盖的一层。
