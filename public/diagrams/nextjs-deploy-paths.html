模块 4.6 · 前端收官

Next.js 两条部署路——我们选 B：静态导出

「内容动态」≠「必须常驻服务」。静态前端 + 后端 API，是更轻、更稳的那条路。
路 A · 没走

常驻 Next 服务

服务器上跑着 next start，Node 进程 7×24
能耐：按每个请求当场拼 HTML（连库、读密钥）
代价：重、费服务器资源
适合：电商/新闻/社媒重内容
Next 全栈还年轻：2025.12 RSC 爆出 CVSS 10.0 漏洞
路 B · 我们选这条

静态导出 out/

build 出干净静态文件夹，Nginx 直接发，服务器无常驻进程
做法：next.config.mjs 加 output: "export"
代价：页面内容 build 时定死；动态数据靠浏览器调 API
适合：博客/文档/纯展示 + 后端 API
轻、稳，和 3.5/4.1/4.4 同一套 Nginx 肌肉记忆

选 B 的落地（和 4.4 只有两处不同）

next.config.mjs 加 output: "export" → npm run build 出 out/ → Nginx root 指向 out/ → location 加 try_files $uri $uri.html $uri/ =404 → reload，/text-lab 直达
静态前端 out/Nginx 直接发的 HTML/CSS/JS
API 通话
独立 Python 后端模块 5 登场：算情感分数、拼音
模块 4 闭环完成：4.1 手写 → 4.2 构建 → 4.3 React → 4.4 数据驱动 → 4.5 Next → 4.6 静态导出上线。
