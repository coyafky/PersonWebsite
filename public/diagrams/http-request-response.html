HTTP 一去一回：两段对称的纯文本

curl -v 里 > 是发出去的请求、< 是收到的响应——平时只看到的 JSON 只是响应体那一行。

请求（去）

调用方发给服务器
① 请求行方法 + 路径 + 版本GET /api/profile HTTP/1.1
② 请求头（若干行）Host / User-Agent / Accept / Authorization…
③ 空行 —— 头说完了
④ 请求体（可选）POST 提交的 JSON 放这；GET 一般没有

响应（回）

服务器回给调用方
① 状态行版本 + 状态码 + 说明HTTP/1.1 200 OK
② 响应头（若干行）Content-Type / Content-Length / Server…
③ 空行 —— 头说完了
④ 响应体真正的正文——我们的 JSON 就放这

状态码家族

2xx成功（200）
4xx请求方的错（404 没找到）
5xx服务方的错

代码 ↔ 规范（main.py）

send_response(200) → 状态行
send_header(...) → 响应头
end_headers() → 那个必须的空行
wfile.write(...) → 响应体
