# 账号和内容归位，以及一条母版流水线的指挥层

## 📇 账号与内容同步

把已经建好的账号、已经发布的内容同步进表格，并做了一件更基础的事：**把账号挂到对应的 IP 实体上**。

| 账号归属 | IP 实体 |
|---|---|
| 知识向账号 | IP-0011 |
| 口播向账号 | IP-0012 |
| 品牌号 | IP-0013 |

**为什么值这一步**：内容和账号一旦有了归属关系，后面做分发和效果统计才有底子。不然一堆账号和一堆文章，对不上谁是谁的。

内容生产库从 14 条补到 **19 条**（新增轮毂工艺、避坑四问、备案、电动踏板、隐形车衣各一条）。

**三个表格工具的坑**：

- 关联字段**必须传数组**（传字符串或对象都不行）
- 某接口投影返回空时，改用另一个写接口的返回结构来验证
- 关联表的记录 ID 藏在返回结构的特定字段里，不在顶层

## 🏗️ 母版生产管线的指挥层

晚上搭了一条完整链路的**指挥技能**：

```
选题 → 产母版 → 工作流线（视频 / 图文）→ 审核 → 存档
```

产出两个技能：一个总管调度，一个专门做审核。

**一处口径修正**：最初把搜索引擎当成选题主力，后来改成 —— **GEOFlow 才是母版生产线**，搜索引擎降级为「选题验证 + 交叉核验」。**谁产出、谁验证，职责分开。**

### 冒烟测试（不是"应该能跑"）

拿一个新做的六帧关键帧做真实审核：**24/25 项通过**。

顺带修了一个污染问题：产出文档里混进了脚本残留（一段没清理干净的临时内容），截断恢复后确认干净。

飞书侧也走通了：母版登记 + 审核报告存档。

**三个新踩的坑**（都记下来了）：

- 表格命令行用 `--base-token` 而不是 `--app-token`（参数名不对会静默走错）
- 批量创建要用指定的 JSON 结构
- 文档创建必须显式指定 API 版本 + 格式 + 从文件读内容

## 关键决策

| 决策 | 理由 |
|---|---|
| 母版产出由 GEOFlow 指挥，搜索引擎只做验证和交叉核验 | 用户口径：GEOFlow 才是生产线 |
| **账号按 IP 实体关联** | 内容与账号归属可追溯，为分发数据打底 |
| **审核流程固化成技能内模板** | 冒烟测试证明可复现（24/25 通过），后续直接套用 |
