# 给学习定一条主线：从「跟着项目学」改成「做一个自己的东西」

> 📌 本篇由当日记忆笔记重建。

## 📚 课程定标

把一个系统课程拉出权威目录：**28 集 / 6 模块**（比旧记录多出一个模块，课程仍在更新）。

于是为它建了：逐集笔记模板（28 份）+ 项目文件 + 内容种子 + 交接文档。

## ⭐ 主线项目定案

**这是这天的关键决定。**

原来的做法是拿自家业务项目当教材 —— 显然能学到东西，但有个问题：**教材是别人的，练习是改别人的东西。**

新方案：**自己做一个 AI 工具箱（AI 导航 / 提示词导航，自建自用）**，把业务项目降级为对照阅读。

理由很直接：**"做一个自己的东西"和"读懂别人的东西"是两种练习。** 前者会逼你面对所有决策，后者只让你面对一部分。

## 🚀 演进路径与部署决策

版本按里程碑推进，**每一版打一个 git tag**：

```
地基 → 纯 HTML+CSS（顺带学 Git） → React 版 → 接 API → 接数据库
```

**部署方案（明确不自购服务器）**：

| 环节 | 方案 |
|---|---|
| 代码 | GitHub |
| 部署 | Vercel |
| 域名 / DNS | Cloudflare |

> 💡 这个组合的意义：**全程零运维。** 学习阶段最不该被消耗的就是服务器维护时间 —— 而这一条恰好是有代价的取舍（自家服务器本来就有）。

另外把学习锚点全量切换了（MISSION / 笔记 / 28 份模板里的旧项目引用都换掉），交接文档按「AI 代码交付契约」写好，激活时机定在学到模块 3 或主动开工。
