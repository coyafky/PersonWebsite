# 1393 个概念的一次大搬家：从「来源分区」改成「知识本体」

## 🧠 架构级重组：目录该按什么分？

昨天把 1398 个概念导进来了，但目录结构是**按来源分的** —— 同一个来源的东西堆一块。

今天就把它改掉。**原则确立为一句话：**

> **知识库目录 = 知识本体分类，不是导入批次/来源的镜像。**

理由很实在：同一个知识主题会散在三个来源分区里，找的时候得翻三遍。而「来源」本该是个**溯源标签**，不该当分类维度。

搬完之后：

| 域 | 概念数 | 重组方式 |
|---|---:|---|
| GEO | 231 | 打散三个来源分区 → **7 个统一模块** |
| AI Agent | 406 | → **10 个模块** |
| Web Dev | — | 9 个主题模块化 |
| 实体卡 | 195 | 按类型分 5 组 |

**全库 1393 个概念，0 个不合规，再无来源镜像层。**

## 🔗 双链全库修复

搬家的连带工程 —— 目录一动，**所有内部链接就全断了**。

修完的结果：

| 项 | 数量 |
|---|---:|
| 处理文件 | 899 |
| 原始双链 | 11,736 |
| **替换为真实文件名** | 8,998 |
| **死链转纯文本** | 2,738 |
| 删除元页 | 54 |
| **最终双链** | 8,936，**0 死链** |

那条「双链目标必须改成真实文件名」的规则不是洁癖 —— **不改的话编辑器会照着链接自动建一堆幽灵空文件**。

顺带把做的事固化成了三个技能：导入管线 / 互引修复 / 合规体检，**把这一轮导入踩过的所有坑都内嵌进去了**。

## 🎨 新建一个生图提示词域

29+ 个概念 / 5 个模块（核心原理 / 模式库 / 视觉语言 / 灵感案例 / 实验对比）。写作方式沿用了博客那套思路：**观点 → 公式 → 证据 → 用法**。

同一天收进 8 条提示词模式（时尚插画、电影感摄影、古风仙侠、画册四宫格、知识信息图、产品海报、手绘笔记、品牌 KV 系统）。

**另外把自家 IP 的资产规范固化了**：2.5 头身 + 场景化头饰 + 深色工装，角色可做知识顾问 / 产品讲解 / 笔记创作者三种身份。技能里新增**逐句拆解表**（每句话对生图起什么作用）。

## 🔄 内容改写管线：从「机构腔」到「活人感」

把「母版 → 平台改写 → 上传 → 登记编号 → 状态回写」这条五步链固化成了技能。

**这天的重点是一处质量问题**：某个平台的产出读起来像**机构教程**（一股模板味）。改造方向：

- 第一人称 / 时间线 / 场景细节 / 情绪 / 口语
- 新写了一份《活人感》规范（七要素 + 证据边界）

**验证通过**：一条 1261 字的产出，零机构腔，同时**保留了对比表 / FAQ / 一句话结论**（这些是给 AI 搜索引用的结构，不能为了口语化删掉）。

### ⭐ 最关键的一条边界

> **活人感 ≠ 虚构事实：只改表达方式，不改数据。**

具体：允许把「适合家庭用户」改写成「**长辈上车费劲**」（同义改写，更具体更好读）；**禁止编造价格、时长、效果**。

这条线很重要 —— 口语化很容易滑向"加点细节让它生动"，而那些细节就是编的。

## 关键决策

| 决策 | 理由 |
|---|---|
| **知识库按知识本体分类，不按来源镜像** | 同一知识散在三处太重复；来源是溯源标签不是分类维度 |
| 双链目标必须改成真实文件名 | 否则编辑器会建一堆幽灵空文件 |
| **活人感 ≠ 虚构事实** | 只改表达不改数据，禁止编造价格/时长/效果 |
| 平台改编稿带日期和平台名命名 | 不同平台的成果可区分、可追溯 |
| 重复副本先 diff 再指针化 | 不确定就先比，不要凭标题判断 |
