# 245 个术语，和 25 条「AI 味」清单

## 📚 术语库：把「说专业一点」变成一件可自动化的事

爬了一个术语站的全站内容：首页 13 类 117 个词条 + 6 个主题页（后端 / AI / 设计 / git / 产品 / 技术），**共 245 个词条**，全部解析成结构化数据（中英对照 + 用户话术描述）。

落成三份产物：

| 文件 | 内容 |
|---|---|
| 学习手册 | 怎么用这套东西 |
| 术语全表 | **245 词**中英对照 |
| **AI 味清单** | **25 条表现**：11 个中文口癖 / 8 个页面模板感 / 6 个不好用的交互 |

还提炼出一个**需求表达范式**：

```
组件/概念 + 状态 + 行为 + 边界条件
```

其中「边界条件」有三问：**空 / 错 / 变**。

**决策**：把这个技能装进 Alma，以后说「说专业一点」「这叫什么」「改写需求」就自动术语化。

> 💬 老实说，245 个词里最有用的是那份 25 条 AI 味清单 —— 因为它是**反面的**。知道该怎么做很难教会，知道什么算「一眼假」反而很好用。

## 🤖 专属 coding agent

- **踩坑**：列出 agent 的命令输出了 29000+ 行权限 JSON，用 grep 截断会**误判成「没注册」**——实际有 8 个 agent。
- 新建了一个 primary 模式的项目级 agent：指定模型 + bash 白名单，其中 `rm -rf` / `git push` / `git reset --hard` / `ssh` 四类高危操作设为**每次询问**。
- **决策**：这个 agent 保持项目级，**不全局挂载**——避免影响其他项目。

## 📖 读书共读

拆完一本 544 页的书，正文从第 9 页起。

- 早间精读 9–11 页（作者自序 → 全书地图 → 科学怀疑论 vs 愤世嫉俗）
- 白天火力全开推 85–99 页的**谬误清单**（相关与因果全拆 / 萨根的龙 / 诉诸无知 / 高级款谬误）
- 晚间推进到 97–99 页

**固化一个偏好**：每页输出**必带「原文框」**（整页原文 + 规整段落）—— 因为要同时读原书，不能只读转述。

## 🎬 资产库 JSON 化

把角色资产从"一份大文件"改造成**每个视角独立 JSON**：

- 五视角各拆独立文件，**共享同一把身份锁**（防止模型每次崩出不同版本）
- 表情库 8 个独立提示词
- 动作库 10 个
- 道具库

**决策**：同一张角色设定图里，**必须完全是同一个角色**（身份锁贯穿到底）。

## 🎬 新项目：轮毂变装

参考了一个很火的「巨人之手给玩偶换装」的结构，把它移植到车上：**玩偶换装 → 车升级**（原厂轮毂 → 运动轮毂 → 护板踏板 → 改色车衣 → 细节 → 亮相）。

**两轮修订，都是减法**：

1. 第一版堆了一堆产品上去 → 改成**只换轮毂**（不同秒段切不同款式）
2. 风格从 Q 版萌系改为**写实**（1:18 合金车模 + 写实的手）

全项目改**横屏 16:9**，六步流水线完整闭环，产出 7 段时间轴：开箱 → 拆原厂 → 五辐枪灰 → 十条锻造 → 复古钢丝 → 金色大 J → 走秀互动。复用之前建的母车与轮毂资产。

## 关键决策

| 决策 | 理由 |
|---|---|
| 术语库装进 Alma | 让「说专业一点」变成自动动作 |
| coding agent 保持项目级 | 不全局挂载，避免影响其他项目 |
| 高危 bash 操作设为每次询问 | 白名单之外的破坏性操作不能默默跑 |
| 角色资产每视角独立 JSON + 共享身份锁 | 防模型崩出多版本 |
| 新项目聚焦轮毂不堆产品 | 多图参考直接切，比产品罗列效果好 |
| 风格改写实 + 16:9 | 产品展示性质，竖屏萌系与定位脱节 |
| 共读必带原文框 | 要同时读原书，不能只读转述 |
