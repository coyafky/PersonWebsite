# 两篇案例上线，和一份「发现脚本与生产路径不符」的交接文档

> 📌 本篇由当日记忆笔记重建。

## 📄 两篇车主案例上线

两篇都是车主案例（一篇地板升级、一篇改色），流程一样：

```
草稿 → 按写作规范重构（补齐元数据 + E-E-A-T + 补缺失章节）
     → 配图（实拍图转 WebP，压缩到约 880 KB）
     → 提交 → 同步到服务器 → 构建 → 部署 → 线上验证全 200
```

**两处做法值得记**：

- **部署前打快照备份** —— 出问题能回滚
- **草稿重构不是照搬**：其中一篇**补齐了缺失的「第三步」施工流程**（草稿里漏了），并去掉了注释噪音

## 📋 交接文档：核对线上实况

给编码工具写部署交接文档时，**逐项实测核对**了线上状态（而不是照着仓库文档抄）——结果核出几件事：

| 项 | 实况 |
|---|---|
| 线上目录 | 是**普通目录，不是软链** |
| 最近部署时间 | 与代码提交时间对得上 |
| 自动部署 | **没有** —— 定时任务里只有证书续期 |
| ⚠️ 仓库里的部署脚本 | **写死的路径与生产不符** |

那条最值得说：仓库里有个遗留的通用部署脚本，**路径写死成另一个位置**，跟生产环境完全不是一回事。

> **处理方式：在文档里明确标注「禁止直接使用」。**

> 💡 这类"文档与实况不符"是交接里最贵的一种债 —— **照着文档做，会做出事故。** 所以这份文档是按实测写的，不是按仓库里的说明写的。

## 关键决策

| 决策 | 理由 |
|---|---|
| 部署前打快照 | 可回滚 |
| **交接文档按线上实测写，不按仓库说明写** | 仓库里的说明可能与实况不符 |
| 遗留脚本标注禁止使用 | 路径与生产不符，照着跑会出事 |
