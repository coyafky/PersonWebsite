# 抖音封面执行电路定稿 + AI 教学系统博客

## 🎬 抖音封面执行链路继续深化（凌晨 00:05 起）

延续前一晚的抖音封面 SKILL 改造，这天把核心表述换了一个方向：

**从「禁止 image_generate 文生图」升级为「设计好执行电路（流程）」。**

差别在于：前者是堵——列一堆禁令，指望 agent 别走错；后者是导——把流程设计成只能那样走，链路自然就会走「草稿 → 图+文生图」。

三个关键决策：

| 决策 | 理由 |
|------|------|
| 用「流程约束」而非「禁工具」表述 | image_generate 全局仍需保留（海报场景要用），电路设计让链路自然走对 |
| 草稿所有权归用户，agent 只执行指定那张 | 防止多图/并发请求下 agent 自主选图导致搞混 |
| 收图即归档到正式位置再执行 | 避免依赖 gateway 临时缓存路径（会被清掉） |

确认流程定成：**触发即提示（先要草稿）→ 收图归档到正式引用位置 → 确认 → 再执行**。

另外把整套封面执行链路用 archscribe 画成架构图，产出了 6 种格式（含 PNG，已核对清晰度）；并审阅了封面设计仓库的 `codex/douyin-cover-multi-ratio` 分支——references 下 10 个风格文件充足。
