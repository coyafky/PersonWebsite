## 第十节：约束条件与精确控制（Constraints & Precision Control）

GPT 生图从 0 到 1 · 第 10 课 · 约束优先级、负面提示词、局部控制与质量验收

前九节，我们学习了如何控制图片中的比例、构图、风格、镜头、光影、材质、参考图与文字排版。

现在进入整个系列中非常重要的一节：如何将“我希望 AI 这样生成”，升级成“我知道如何约束、检查和修正 AI 的生成结果”。

假设我们遇到三个真实工作场景：

- 场景 A： 上司要求更换海报背景，但原来的 Logo、二维码和所有文字都必须保持不变。
- 场景 B： 需要为 100 款新能源汽车制作统一风格的商品图片，只有车型与参考图片不同。
- 场景 C： 用车辆照片与轮毂产品图制作安装效果图，不能改变轮毂辐条结构，也不能改动车身。

这些任务的共同难点是：不仅要知道生成什么，更需要知道什么不允许改变。

本节将建立一套适合实际商业工作的精确控制体系。

### 10.1 首先理解：什么是约束条件？

约束条件（Constraints）是对生成任务设定的要求、限制与验收边界。

在提示词工程中，可以把要求分成五种。

| 约束类型 | 英文         | 作用               |
| -------- | ------------ | ------------------ |
| 正向约束 | Positive     | 明确必须生成什么   |
| 负向约束 | Negative     | 明确不能出现什么   |
| 保持约束 | Preservation | 指定必须保留的内容 |
| 范围约束 | Scope        | 限制允许修改的区域 |
| 验收约束 | Validation   | 明确什么结果算合格 |

例如：

普通提示词：

> 把这辆车的轮毂换成另一款，其他不变。

结构化提示词：

> 使用图片 A 作为车辆基础，仅替换四个车轮的轮毂金属部分。新轮毂以图片 B 为唯一产品结构参考。必须保持车辆造型、轮胎、车身颜色、背景与摄影角度不变。验收时检查辐条数量、镂空形状、中心盖和透视是否正确。

第二种写法更清晰，但也必须明确：文字约束能够降低歧义，并不等于生成模型一定会严格执行。

### 10.2 第一部分：P0 / P1 / P2 约束优先级

当一张图片包含很多要求时，首先需要确定它们之间的优先级。

我们采用三个层级：

### P0

必须满足 · Critical

违反就不能交付。

例如：车型正确、产品结构真实、价格正确、Logo 不变、二维码可扫描。

### P1

优先满足 · Important

直接影响画面质量和设计规范，通常需要修正后才能通过品牌验收。

例如：画面比例、产品占比、主体位置、排版层级、统一品牌配色。

### P2

可优化 · Flexible

在不影响 P0、P1 的前提下，允许艺术性调整。

例如：背景渐变程度、局部高光、接触阴影、细小装饰。

#### 一个关键规则：高优先级要求不能被低优先级美化覆盖

例如，用户指定的轮毂是五辐结构，而 AI 为了让画面更好看，将它生成了多辐结构。

即使画面很高级，这张图也属于 P0 失败。

同样，对于价格、产品型号和品牌文字，只要出现错误，就不应该因为“整体设计好看”而通过验收。

P0/P1/P2 是我们建立的任务管理规范，不是 GPT Image 模型官方的强制优先级参数。

### 10.3 第二部分：负面提示词（Negative Prompts）

负面提示词的作用，是告诉模型不希望出现哪些内容或视觉特征。

但我们需要区分两类：

第一类：禁止出现的内容。

例如：

> 画面中只能出现一台汽车，不出现行人、其他车辆、复杂装饰或水印。

第二类：禁止发生的修改。

例如：

> 不改变原车灯组、前脸、车轮位置、车身颜色以及背景。

这两类约束的用途不同。

负面约束的正确组织方式

较弱的写法

不要错误，不要变形，不要 AI 味，不要乱七八糟。



更明确的写法

画面只能出现一台车辆。

车身完整入镜，禁止裁切车头和车尾。

不添加其他车辆或人物。

不改变参考图中的灯组、轮毂和车身轮廓。

不出现多余文字、水印与虚假的品牌标识。

#### 负面提示词的三个原则

1. 具体化：说明实际禁止的内容，而不是只写“不要不好看”。
2. 相关性：只约束当前任务可能遇到的错误，不要无限堆砌无关词语。
3. 正负配合：在禁止错误的同时，明确告诉模型正确的目标是什么。

例如，与其只写“不要塑料皮肤”，不如写：

> 保留真实肤色变化与适量细微皮肤纹理，避免过度磨皮和蜡像般的高光。

对于 GPT Image 这类通过自然语言接收指令的图像模型，负面约束可以直接写在提示词中；不应假定它一定具有其他图像生成系统中的独立负面提示词参数。

### 10.4 第三部分：修改范围控制（Editing Scope）

这一部分直接对应我们在第八节学习过的局部编辑。

修改范围控制的核心是把画面分成两部分：

- Editable Region：允许编辑区域
- Protected Region：受保护区域

例如，一张新能源汽车电商主图：

修改范围划分示意

保护区域 A · 品牌栏

LANHUI 蓝辉轻改



可编辑区域 · 车辆主视觉

保护区域 B · 卖点栏

原车开模｜无损安装｜安全防夹

蓝色区域为固定排版，绿色区域为动态产品主视觉。这是区域划分示意，不是实际的图像遮罩。

如果需要更换中间的车辆，那么顶部 Logo 和底部卖点就不应该参与生成式重绘。

#### 两种修改方式

| 实现方式       | 特点                         | 适合任务                         |
| -------------- | ---------------------------- | -------------------------------- |
| 提示词约束     | 通过自然语言要求只修改某处   | 允许一定视觉误差的创意编辑       |
| 遮罩及图层控制 | 通过实际区域隔离限制编辑范围 | 需要精确保护文字、Logo、产品结构 |

对于正式商品图，尤其是批量制作，建议在工程层面拆分主视觉和文字图层。

### 10.5 第四部分：提示词冲突处理（Prompt Conflict Resolution）

提示词越长，不一定越精确。

如果包含互相矛盾的要求，模型可能出现不可预测的取舍。

例如：

> 使用 85mm 长焦镜头，近距离拍摄广角夸张透视，同时完整展示人物和非常宽阔的周围环境。

这里混合了不同的镜头效果，没有说明哪个优先。

#### 六种常见提示词冲突

| 冲突类型   | 错误示例                            | 解决方法                             |
| ---------- | ----------------------------------- | ------------------------------------ |
| 构图冲突   | 面部特写，同时完整展示全身          | 选择一种景别，或拆成两张图           |
| 光影冲突   | 正午烈日，同时没有任何硬阴影        | 改为阴天或添加柔光条件               |
| 风格冲突   | 完全写实，同时保持纯二维赛璐璐效果  | 明确主风格与允许的次风格             |
| 结构冲突   | 原车完全不变，同时将 SUV 改成轿车   | 明确具体允许变化的结构               |
| 文字冲突   | 只允许 2 行标题，但指定一整段长文案 | 缩减文案或增加文字空间               |
| 参考图冲突 | 图片 A、B 都是唯一车型依据          | 指定一个主参考，另一个只负责特定信息 |

#### 建立提示词冲突处理流程

收集所有生成要求



识别目标、限制与参考素材



检查是否存在相互矛盾的条件



无冲突

进入生成



存在冲突

按优先级解决或拆分任务



生成最终无明显冲突的 Prompt

#### 具体案例：轮毂替换任务

上司说：

> 把原车轮毂替换成我提供的轮毂，车身和角度不变，产品结构必须一模一样，但最终画面要更有科技感。

这里可能存在“科技感美化”与“产品结构不变”的冲突。

解决方法：

- P0：车辆结构、轮毂产品结构不变。
- P1：安装位置、镜头透视与真实照片协调。
- P2：通过背景色、环境光和辅助装饰增强科技感。

如果 P2 与 P0 冲突，就牺牲 P2，而不是改变真实产品。

### 10.6 第五部分：单变量实验（One Variable at a Time）

这是整套生图学习方法中非常值得长期使用的原则。

每次实验只主动修改一个主要控制变量，尽量固定其他条件。

举例：我们想研究不同光线对少女肖像的影响。

| 服装 | 米白色长裙   | 固定 |
| 背景 | 同一片草原   | 固定 |

#### 实验中最容易忽略的问题：随机性

即使两段提示词只相差一个词，生成模型也可能改变人物表情、背景细节和构图。

因此，要尽量统一：

- 模型版本及生成参数。
- 输入图片与参考顺序。
- 基础提示词。
- 输出比例与质量设置。
- 可用时固定随机种子。
- 每个条件重复生成若干次进行比较。

需要强调：不是所有 GPT Image 使用方式都支持设置随机种子；即便可以设置，也不代表跨模型版本得到完全相同的图片。

此外，控制变量实验与生产编辑的目标不完全相同。教学实验追求区分因素，生产编辑追求交付正确的图片。

### 10.7 第六部分：生成结果验收（Image Quality Validation）

有了约束条件后，还需要建立明确的验收机制。

对于商业图片，我建议采用硬性门槛 + 视觉质量评分的双层检查机制。

#### 第一层：P0 硬性门槛

任何一个关键项目失败，都不得直接交付。

例如：

- 车辆型号错误。
- 产品结构与实物不符。
- 中文价格、型号、品牌名称错误。
- Logo 被重新绘制变形。
- 二维码无法识别。
- 产品数量或指定结构错误。

#### 第二层：P1 / P2 视觉评分

可以采用以下示例权重，辅助判断是否需要优化。

视觉质量评分

## 80/ 100

建议继续优化

构图与主体占比

4 / 5 · 权重 25%

光影与材质

4 / 5 · 权重 20%

排版与可读性

4 / 5 · 权重 25%

品牌风格一致性

4 / 5 · 权重 20%

整体视觉完成度

4 / 5 · 权重 10%

发现至少一项 P0 硬性错误

判定：需要进一步优化

85 分是教学用的示例门槛，并不是行业统一标准。仍需进行独立的事实和产品检查。

需要注意：这套评分是我们为商业设计建立的内部评价示例，不代表自动质量检测已经完成。

### 10.8 第七部分：构建可复用的约束模板（Constraint Template）

为了将前九节知识整合，我们需要设计一套所有图片生成任务都可以调用的约束模块。

## GPT Image · Precision Control Template V1.0

### 01. 任务目标（Objective）

本次需要生成或修改：

[填写图片目标]

预期用途：

[电商主图 / 博客图片 / 海报 / 社交媒体]

### 02. 参考素材（References）

图片 A：[主要主体参考]

图片 B：[产品或场景参考]

图片 C：[品牌或风格参考]

必须明确每张参考图的职责，不允许错误混用。

### 03. P0 · 必须满足的约束

- [不可改变的主体特征]
- [不可改变的产品结构]
- [准确的文字与品牌信息]
- [其他必须满足的业务条件]

任何 P0 条件失败，都不能直接交付。

### 04. P1 · 重要设计约束

- 图片比例：[比例]
- 构图方式：[构图]
- 主体位置：[位置]
- 视觉风格：[风格]
- 镜头语言：[镜头]
- 光影色彩：[光影]
- 品牌规范：[要求]

### 05. P2 · 可优化内容

- 背景细节
- 光线与阴影的微小变化
- 装饰元素
- 非关键的视觉细节

以上内容允许调整，但不能违反 P0 和 P1。

### 06. 负面约束（Negative Constraints）

明确禁止：

- [禁止出现的元素]
- [禁止修改的内容]
- [不合理的视觉效果]
- [不允许添加的文字或装饰]

### 07. 修改范围（Editing Scope）

允许修改：

[具体区域或对象]

必须保护：

[具体区域或对象]

### 08. 冲突处理（Conflict Resolution）

当要求冲突时：

1. 优先满足 P0。
2. 保证 P1 设计规范。
3. 在不影响前两者的情况下调整 P2。
4. 无法兼容的 P0 要求必须先澄清，不能自行决定放弃哪一项。

### 09. 输出规格（Output）

图片比例：[比例]

分辨率：[实际支持的尺寸]

输出用途：[平台]

### 10. 验收标准（Validation）

逐项检查 P0、P1 和 P2。

发现错误时明确记录失败项。

如果生成式编辑无法满足精确保护要求，采用原图、遮罩、图层合成等确定性处理方式。

这一模板可以作为你以后所有生图任务的基础约束模块，再根据实际任务追加具体要求。

### 10.9 第八部分：100 张图片批量生成时如何应用约束？

回到前面提过的工作场景：

上司要求制作 100 张新能源汽车电动踏板商品主图。

我们已经知道应该拆分常量与变量，现在进一步加入约束和验收规则。

| 配置类型   | 字段     | 示例                         |
| ---------- | -------- | ---------------------------- |
| Constant   | 画幅     | 1:1                          |
| Constant   | 背景     | 白灰色摄影棚                 |
| Constant   | Logo     | 原始 LANHUI 品牌素材         |
| Constant   | 版式     | 顶部标题、中间车辆、底部卖点 |
| Variable   | 车型     | 问界 M9、理想 L9 等          |
| Variable   | 车辆图片 | 每款车型对应的参考图         |
| Variable   | 产品 SKU | 经过适配确认的踏板型号       |
| Variable   | 产品图片 | SKU 对应的原始产品图         |
| Constraint | P0       | 车型、产品、品牌与文案正确   |
| Constraint | P1       | 统一比例、构图与视觉风格     |
| Validation | 验收结果 | PASS / FAIL / REVIEW         |

#### 推荐的批量生产架构

Master Prompt + Constraint Template

母版提示词与约束规范



100 条行级数据

车型、图片、SKU、标题



输入预检查

数据完整、产品适配、参考素材有效



批量生成车辆主视觉

逐行装配提示词与参考图片



固定模板排版合成

叠加原始 Logo、准确中文、卖点





PASS

保存并交付



FAIL / REVIEW

修复、重试或人工审核

#### 批量失败处理

100 张图片不应该只分成“成功”和“失败”两种状态。

建议增加：

- `PENDING`：等待生成。
- `GENERATING`：正在生成。
- `REVIEW`：需要人工审核。
- `PASSED`：验收通过。
- `FAILED`：明确不合格。
- `RETRYING`：正在重试。

其中，车型与配件适配真实性、Logo 和文字准确性应当有明确的数据核对过程，而不能仅依赖模型对图片的主观评价。

\# 精确控制生图提示词 【任务】商品主图批量生产 把当前商品图中的车型替换为问界 M9，使用对应的实拍车辆参考图和已确认的电动踏板产品图。 【P0 必须满足】 车型必须与对应参考图匹配，踏板必须匹配已核验的产品 SKU，Logo 和文字使用原始素材。 【P1 重要要求】 全批次统一画幅比例、品牌色、构图和产品展示区域。 【P2 可调整】 局部背景渐变、非关键的反射与阴影。 【负面约束】 禁止改变产品结构，不添加不存在的产品细节或虚假卖点。 【画幅】1:1 【修改边界】 只修改任务中明确授权的内容，未授权区域尽量保持原样。对于必须逐像素不变的元素，优先进行原图合成。 【冲突处理】 P0 高于 P1，P1 高于 P2。发现无法同时满足的 P0 条件时先标记冲突，不擅自放弃要求。 【验收】 检查 P0 是否全部通过，再检查构图、风格、材质和画幅。任何 P0 错误均不得直接交付。

### 10.12 第十节知识总结

通过这一节，我们已经从单纯描述图片，升级到了任务级的提示词工程。

核心公式：

精确生图控制 = 目标描述 + 优先级约束 + 修改范围 + 冲突检测 + 质量验收 + 失败修复。

更进一步，前十节的知识已经可以整合为一条完整链路：

从 0 到 1 的完整生图流程

图片目标 → 比例 → 构图 → 风格 → 镜头 → 光影 → 材质 → 参考图 → 文字排版 → 精确约束 → 生成 → 验收 → 迭代

最重要的认知是：Prompt 负责表达意图，工作流负责执行控制，验收机制负责确认结果。

即使编写了很长的提示词，也不能取代真实产品数据、原始品牌素材、确定性编辑和必要的人工复核。
