# 2026-W31 第 31 周周志

## ✅ 本周进展

### Agent Reach：给 Agent 装上阅读世界的眼睛

安装了 Agent Reach v1.5.0（15 个平台、多后端路由的信息获取工具）。当天体检通过 5/15 渠道：YouTube、B 站、V2EX、RSS、Web 全部可用，GitHub 实测也能用。国内场景走直连渠道（B 站搜索 / GitHub / RSS / 小红书），不配代理先把核心链路跑起来，国外平台等真需要时再解锁。

### 工具取舍：卸载 OpenClaw

OpenClaw 从云端方案（W20 定过腾讯云 Lighthouse 部署）到本地装的折腾，本周正式卸掉。结论很明确：**Agent 工具要少而精**——信息获取交给 Agent Reach，知识沉淀交给 Hermes，内容输出交给 PersonalWebsite，三件套各管一段，不重复造轮子。

### Mac 瘦身：第一批清理见效

体检发现内存 15G used、空闲仅 113MB，常驻服务一堆。第一批清理：停掉 highschool-english gateway（省 ~219MB）、停掉 MongoDB（省 ~109MB）、删掉百度网盘 / Kimi / 腾讯字体助手的自启项、npm 卸载两个不用的包。效果：空闲内存 113MB → 1164MB，resident 内存从 5.3G 降到 4.5G。Hermes 剩下 6 个 gateway 保留（在用），双 Postgres 和 Clash 暂时不动。

### CoyaWork 正式设定为公司工作目录

把 `CoyaWork` 明确定位为**公司工作目录**（不是个人主目录）：
- 写进 README 使用手册：定位、编号体系（00-inbox → 99-person）、工作流约定、Agent 规矩
- CLAUDE.md 顶部加定位说明，个人知识/笔记归 CoyaPersonal，博客输出归 PersonalWebsite
- 根目录散落文件全部归位：GEO 调研 → 70-knowledge、周复盘 → 40-review、报告模板 → 60-reports、破茧行动 PDF → 90-archive

### 内容管线：周复盘 → 周记

把 `coya-blog-writer` 技能升级成双管线：CoyaWork 的周复盘（40-review/weekly）自动映射成网站周记（content/weekly/），项目资料（10-work/projects）映射成项目页（content/projects/）。以后周复盘写一次，周记就是格式化的产物，不用重新组织一遍。

## ⚠️ 关键问题

- **工作日志有断层**：07-27 ~ 07-29 的每日记录缺失，本周复盘只有周四、周五有据可查。连续性是复盘体系的生命线，这块要立个规矩。
- **周记断更 10 周**：网站上最后一期是 W21，W22-W30 全部空白。旧流程太重是主因，新管线就是来治这个的——但要补的坑还不少。

## 💡 本周思考

**工具链的价值不在数量，在分界清晰。** 这周最大收获不是装了多少工具，而是想明白了三件事各归谁管：信息进来（Agent Reach）、知识存住（CoyaPersonal + Hermes）、内容出去（PersonalWebsite）。工具边界清楚了，连卸载都变得轻松——OpenClaw 说卸就卸，因为它的生态位已经被更专的工具占掉了。

**复盘体系最怕的不是没内容，是没习惯。** 断更 10 周的周记不是没有素材，是每次写都要重新搭格式、找数据、组织语言，成本太高。现在 CoyaWork 把周复盘模板化、管线化之后，写周记的成本从"写一篇文章"降到"审一份草稿"，习惯才养得起来。
