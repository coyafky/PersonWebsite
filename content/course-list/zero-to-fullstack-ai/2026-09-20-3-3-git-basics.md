## 本节要点

- 版本管理不是高级流程，而是**后悔药**：改坏了能回到上一版。AI 写代码时尤其重要——第一版能跑、第二版崩了，你得有可靠的上一版存档。
- Git 只管一个**目录**（仓库 repository），不是整台电脑；一个项目一个仓库，互不影响。
- 一次 `commit` = 一个存档点，记录：当时文件状态 + 时间/作者 + 提交说明。
- 流程三段：改文件 → `git add`（放进暂存区）→ `git commit -m "说明"`（落成存档点）。
- `.gitignore` 提前写，把无关文件（如 macOS 的 `.DS_Store`）排除在版本管理外。
- 小步提交、说明当场写、越早建 `.gitignore` 越好。

## 笔记正文（讲义整理）

### 为什么要学 Git

已经有了 `index.html`、`style.css`、`script.js` 三个文件。接下来最容易发生：改了几处页面突然坏了、想不起改了什么、想回退却没有回退点。AI 写代码场景也一样——让 AI「回到上一版」，上一版却没被可靠保存。

Git 解决的就是：**在改动前后留下清晰历史，随时回看、比较、回退。**

### 仓库是什么

Git 的管理单位不是整台电脑，也不是单个文件，而是一个**目录**。你让 Git 开始管理 `~/zero-to-tech`，这个目录就成了**仓库（repository）**。电脑里可以有很多仓库，互不影响。

### 五步上手

**1. 确认安装**：`git --version`，看到 `git version 2.x.x` 即可。

**2. 配身份（每台电脑一次）**：

```
git config --global user.name "你的名字"
git config --global user.email "你的邮箱"
```

**3. 初始化仓库**：

```
cd ~/zero-to-tech
git init
git status        # 三个文件多半显示 Untracked files
```

**4. 先写 `.gitignore`**（忽略 macOS 的 `.DS_Store`）：

```
.DS_Store
```

`.gitignore` 本身要提交（它是项目规则），`.git` 不用写进去。

**5. 第一次提交**：

```
git add .                     # 全部改动放进暂存区
git status                    # 确认在 Changes to be committed
git commit -m "第一次提交"
```

然后**立刻再做一次小改动**（改一行标题），再走一遍 `add` + `commit -m "修改首页标题文案"`——这样才开始形成版本管理的直觉：**每次有意义的改动，都落成一个可解释、可回退的提交。**

### 三个常见误区

- **只有大改动才值得提交** → 错。小步提交比大包提交更安全。
- **说明后补** → 错。提交说明就是「当时为什么这么改」，后补必失真。
- **`.gitignore` 可有可无** → 错。越早建越干净。

## 关键概念

- **仓库（repository）**：被 Git 管理的一个目录，是版本历史的单位。
- **commit（提交）**：一次存档点，记录文件状态 + 时间/作者 + 说明。
- **暂存区（staging）**：`git add` 后、`commit` 前的中间地带——先挑好这次要存哪些改动。
- **`.gitignore`**：告诉 Git 忽略哪些文件不纳入版本管理（如 `.DS_Store`）。
- **`git status`**：查看当前状态的后视镜——哪些改了、哪些已暂存、哪些还没跟踪。

## 代码 / 实操

```
git --version
git config --global user.name "你的名字"
git config --global user.email "你的邮箱"

cd ~/zero-to-tech
git init
# 写好 .gitignore（.DS_Store）
git status
git add .
git status
git commit -m "第一次提交"

# 改一行标题，再来一次
git add .
git commit -m "修改首页标题文案"
```

## 我的收获

1. Git 不是高级流程，是后悔药——存档点越密，改坏时越不慌。
2. `add` 和 `commit` 是两步：先挑这次存什么，再落存档；这个设计让每次提交只装一类改动。
3. 提交说明当场写人话，是写给一周后、AI 接手、未来的自己看的。
