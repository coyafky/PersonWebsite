本文中的文件、代码和终端输出用于检查组件，不表示命令已经在真实项目中执行。组件只展示文本，不执行命令。

</Callout>

## 先把职责放进目录

文件结构先表达职责，代码示例再解释关键实现。这样读者可以先定位入口，再决定是否需要阅读细节。

<FileTree title="检查工作流目录" items={[
  { name: "mdx-authoring", children: [
    { name: "reader.ts", comment: "读取仓库内容" },
    { name: "checker.ts", comment: "检查作者契约" },
    { name: "fixtures", children: [
      { name: "valid.mdx", comment: "合法样板" },
      { name: "unsafe.mdx", comment: "拒绝用例" }
    ] }
  ] }
]} />

目录树只说明文件职责，不代表仓库中存在这组示例文件。

## 代码围栏保留关键上下文

代码围栏适合展示单个实现片段。文件名帮助读者定位，行号和重点行帮助读者聚焦变化。

```typescript title="checker.ts" showLineNumbers {2-3}
const source = readMdxFile("fixtures/valid.mdx");
const result = checkMdxAuthoring(source);
if (!result.ok) throw new Error("作者契约未通过");
```

## 对比同一配置的两种写法

只有在写法确实并行、且读者需要来回比较时，才使用代码切换。

<CodeTabs label="配置格式" items={[
  { label: "JSON", language: "json", filename: "workflow.json", code: '{\n  "status": "draft",\n  "needsReview": true\n}' },
  { label: "YAML", language: "yaml", filename: "workflow.yaml", code: 'status: draft\nneedsReview: true' }
]} />

两种写法表达相同约束。`CodeTabs` 只负责展示和复制，不执行其中的内容。

## 区分命令和输出

终端组件让命令与结果保持视觉分离，也避免读者误以为页面会自动运行命令。

<Terminal title="检查流程 · 示例输出" lines={[
  { command: "npm run typecheck", output: "类型检查通过（示例）" },
  { command: "npm run mdx:check -- docs/examples/mdx/code.mdx", output: "MDX 校验通过（示例）" }
]} />

复制按钮只提取命令，不包含提示符和输出。

<Accordion title="为什么不把所有代码都放进 CodeTabs？">

单个代码片段用普通围栏更容易阅读。只有多个并行实现需要对照时，标签页才有额外收益。

</Accordion>
