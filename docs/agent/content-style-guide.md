# Content Style Guide — 内容写作规范

> 本文件是本站**中文内容写作的唯一权威规范**。写 blog、weekly、projects、course-list、book-list、learning、diary、career 任何面向站点的中文内容前，先读它。
>
> 上游标准：阮一峰《中文技术文档的写作规范》（[ruanyf/document-style-guide](https://github.com/ruanyf/document-style-guide)，公共领域）。该规范共七节，全文已蒸馏进本文件，**写作时无需联网**。
>
> 效力：硬性。与其它文档冲突时以本文件为准。上游未覆盖、本项目自行约定的部分，标题后标 `[项目]`。

---

## 1. 标题

### 层级

标题分四级：一级是文章标题，二级是主要部分的大标题，三级是二级下面的小标题，四级是三级下面某一方面的小标题。

```markdown
# 一级标题

## 二级标题

### 三级标题

#### 四级标题
```

### 原则

（1）一级标题下不能直接出现三级标题，中间必须补齐二级标题。

（2）避免孤立编号。同级标题只有一个时应当省略，把它降为正文段落。

（3）下级标题不重复上一级标题的名字。

（4）谨慎使用四级标题。三级标题下有并列内容时，改用项目列表或 `**（1）**` 式并列，保持层级简单。

`[项目]` 一级标题由 frontmatter 的 `title` 渲染，所以正文里**不写 `#`**，正文标题从二级开始。

## 2. 文本

### 字间距

（1）全角中文与半角英文之间加一个半角空格。

```
错误：本文介绍如何快速启动Windows系统。

正确：本文介绍如何快速启动 Windows 系统。
```

（2）全角中文与半角阿拉伯数字之间，有没有空格都可以，但**全文风格必须统一**，不能两种混用。

（3）英文单位不翻译时，数字与单位符号之间留出空隙：`16 GB`、`1 h = 60 min = 3,600 s`。

（4）半角英文、半角数字与全角标点之间**不留空格**。

```
错误：他的电脑是 MacBook Air 。

正确：他的电脑是 MacBook Air。
```

### 句子

（1）避免长句。不含标点的单句，或逗号分隔的句子构件，长度尽量在 20 字以内；20～29 字可以接受；30～39 字必须语义明确；**多于 40 字任何情况下都不接受**。逗号分割的长句总长不超过 100 字或正文三行。

（2）尽量使用简单句和并列句，避免复合句。

（3）同一个意思尽量用肯定句，不用否定句。

（4）避免双重否定。

### 写作风格

（1）尽量使用主动语态，不使用被动语态。

（2）不使用非正式的语言风格。

（3）不使用冷僻、生造或文言文的词语，使用现代汉语的常用表达。

（4）用对「的」「地」「得」。形容词＋的＋名词，副词＋地＋动词，动词＋得＋副词。

（5）代词（其、该、此、这）必须明确指代内容，保证只有一个含义。

（6）名词前不要堆过多的形容词。

### 英文处理

（1）英文原文使用复数形式时，译成中文要还原为单数。

（2）外文缩写可用半角圆点表示：`U.S.A.`、`Apple, Inc.`。

（3）中文语境下的省略号用 `⋯⋯`，不写 `...`。

（4）英文书名或电影名改用中文表达时，双引号改为书名号。

（5）英文词汇第一次出现时，在括号中给出中文标注，此后直接用缩写。例：`IOC（International Olympic Committee，国际奥林匹克委员会）`。

（6）专有名词每个词首字母大写，非专有名词不大写。

## 3. 段落

- 一个段落只讲一个主题，或只有一个中心句。
- 中心句放段首，概述全段，后面的句子为中心句服务。
- 一段不超过七行，**最佳不超过四行**。
- 使用陈述和肯定语气，避免感叹语气。
- 段落之间空一行。
- 段首不留空白字符。

### 引用

引用第三方内容时注明出处。全篇转载要在开头显著位置注明作者与出处，并链接至原文。使用外部图片必须在图下或文末标明来源。

`[项目]` 本站**不引用外部图片 URL**（来源易失效，且有跨域与隐私问题），所以这条只在引用文字内容时适用。

## 4. 数值

- 阿拉伯数字一律使用半角，不得使用全角。
- 千位以上加千分号。四位数可选（`1000` 与 `1,000` 都可以），**四位以上必须加**。
- 货币使用阿拉伯数字，数字前写货币符号或数字后写中文名称：`$1,000`、`1,000 美元`。
- 数值范围用波浪线 `～` 或一字线 `—` 连接。带单位或百分号时，两个数字都要带上：`132 kg～234 kg`、`67%～89%`。
- 增加用「增加了」（增量）与「增加到」（定量），减少用「降低了」与「降低到」。**不得用「降低 N 倍」「减少 N 倍」**，改用「降低百分之几」「减少百分之几」。

## 5. 标点符号

原则：中文语句一律用全角标点；整句为英文时用半角标点；句号、问号、叹号、逗号、顿号、分号、冒号不得出现在行首；**点号不得出现在标题末尾**，标号（引号、括号、破折号、省略号、书名号等）可以。

| 符号 | 规则 |
|---|---|
| 句号 `。` | 中文句末用全角句号。句末用括号加注时，句号在括号之外 |
| 逗号 `，` | 句子内部的一般性停顿。避免一逗到底 |
| 顿号 `、` | 句子内部的并列词用全角顿号，并列词即使是英文也用顿号。末项尽量用「和」连接 |
| 分号 `；` | 复句内部并列分句之间的停顿 |
| 引号 `“ ”` | 引用用全角双引号，前后不同。引号内再用引号时，外层双引号、内层单引号 `‘ ’` |
| 括号 `（）` | 补充说明用全角圆括号，括号前后不加空格 |
| 冒号 `：` | 全角冒号引出解释和说明。**表示时间用半角冒号**，例 `8:00` |
| 省略号 `⋯⋯` | 占两个汉字位、含六个点，不写 `。。。` 或 `...`。不与「等」连用 |
| 感叹号 `！` | 应使用平静语气，尽量避免。不得多个连用 |
| 破折号 `——` | 占两个汉字位，用于进一步解释 |
| 连接号 | 名词复合与图表编号用半角 `-`（`氧化-还原反应`、`图 1-1`）。数值范围用 `～` 或 `—` |

## 6. 文档体系 `[项目]`

### 内容文件命名

站点内容文件名 = `content/<栏目>/<YYYY-MM-DD>-<slug>.md`（或 `.mdx`）。

- 文件名**不含空格**，**只用半角字符**，中文不进文件名。
- 建议全小写，单词之间用半角连词线：`advanced-usage` 优于 `advanced_usage`。
- 例外：`README`、`LICENSE` 这类说明文件可以用大写。

### frontmatter

字段以 `lib/content/schemas.ts` 的 Zod schema 为准，这里不抄写，以免规则漂移。共通必填项是 `title`、`date`、`summary`、`status`；blog 另有 `tags`、`lang`、`updated`、`mood`、`source`。新稿一律 `status: draft`。

## 7. 图例规范

### 7.1 总原则

**信息用图，氛围用画。**

承载精确信息的图（数据、关系、流程、结构）必须由文本或代码生成，做到可核验、可修改、可版本控制。只有氛围、隐喻、概念意象才交给 AI 生图。

图表不是装饰。**能一句话说清的关系不要出图，说不清的关系必须出图。**

### 7.2 判断逻辑

写完正文后执行以下四步。

**第一步 · 通读全文，标出「关系密集段」。**

一段文字满足以下任一条，就是候选位置：

- 三个及以上并列项（分类、清单、要点）
- 有先后顺序或阶段（先、然后、最后）
- 有层级或包含关系（A 属于 B，B 属于 C）
- 有分支或条件（如果……否则……）
- 有数值对比（多组数据的横向比较）
- 有因果链或传递关系（A 影响 B，B 影响 C）
- 概念之间是对比或取舍关系

**第二步 · 判断这段需不需要图。**

判据只有一条：**只用文字，读者读一遍能不能记住这个关系？** 需要回看、需要在脑子里画一遍，就该出图。反过来，两三个词的简单并列不必出图。

**第三步 · 选档。** 见 7.3 的矩阵。

**第四步 · 定位插入点。**

- 图放在**它服务的那个段落之后**，先文后图，不要先图后文。
- 图下必须有一句解读或图注，说明这张图让人看到什么。
- 不得孤立悬挂。正文里没有任何一句话指向它的图，删掉。

### 7.3 三档工具选择矩阵

| 档 | 工具 | 用在 | 不适用 |
|---|---|---|---|
| **A · mermaid** | ` ```mermaid ` 围栏代码块，站内原生渲染 | 流程图、时序图、状态机、ER 图、类图、甘特图、简单层级、分支决策 | 需要精确排版或品牌视觉。节点超过 15 个会糊成一团 |
| **B · HTML/SVG 转 PNG** | 手写 HTML 或 SVG，用 Playwright 截图 | 编辑级排版、精确坐标的架构图、嵌套与包含结构、矩阵与象限、时间线 | 内容会频繁改动。PNG 是死图，改一次就要重截一次 |
| **C · AI 生图** | `micu-image` MCP（gpt-image-2） | 封面、氛围图、概念隐喻、抽象意象 | **任何含具体数据、名称、代码或精确关系的图** |

选档顺序：**先问 A 能不能表达。** 大部分结构化关系 mermaid 都能画，而且它可版本控制、零成本、能被搜索引擎读到。A 表达不了（要精确排版、要编辑级质感）才升到 B。**C 只用于不承载事实的图像**，一旦发现自己在 prompt 里塞具体数字或专有名称，说明选错档了。

### 7.4 各档落地

**A · mermaid**

直接写围栏代码块即可，站内已接好（`components/mermaid.tsx`，mermaid ^11.15.0，`securityLevel: "strict"`，`theme: "default"`）。仓库现有 63 个内容文件已在用。

注意：`securityLevel: "strict"` 下，节点文字里的 HTML 会被当作纯文本，写标签时不要指望加粗或换行标签生效。

**B · HTML/SVG 转 PNG**

- 截图工具：`~/.config/alma/tools/pw-shot`（Playwright 1.63.0，`deviceScaleFactor: 2`）。不要用 `npx playwright screenshot`，它没有 `deviceScaleFactor`（出图糊）、不能注入 CSS 隐藏工具栏、不能锁定 `colorScheme`。
- 需要编辑级图表时用 `diagram-design` 技能。它的校验器仓库已永久化在 `~/.config/alma/tools/diagram-design-repo`，含三十多个校验器。
- 两个已经踩过的坑：
  - `verify-geometry.py` **只校验节点与 label mask 的重叠，不校验裸 `<text>`**。说明文字放错位置会被方块盖住，而它照样报零发现。它报通过**不等于**图看着对，出图后必须自己看一眼。
  - 模板常用 `min-height: 100vh` 加 flex 居中，整页截图会留大片空白。**要做元素级裁剪**，只截内容容器。
- 产物落 `public/images/blog/<slug>/`，用 `npm run images:add` 导入，不要手写路径。

**C · AI 生图**

- 通道是 `micu-image` MCP，模型 gpt-image-2。动手前先调 `server_info`，拿当前的能力矩阵与尺寸约束。
- 尺寸：1K 档（`1024x1024`、`1536x1024`、`1024x1536`）稳定。最大边达到 1600 会自动切 pro，约 80 秒一张。
- 局部修改走 `image_edit`，多图风格融合走 `image_multi_reference`。**不要用生图工具去改一张需要保持像素一致的信息图。**
- 产物同样落 `public/images/blog/<slug>/`，`alt` 写图传达的信息，不要重复写「图片」或文件名。

### 7.5 密度与克制

- 一篇文章的图**不超过 3～5 张**。图多不等于立体，堆图会稀释重点。
- 正文已用表格说清的内容**不再出图**。两者是替代关系，不是叠加关系。
- 800 字以内的短文通常 0～1 张。
- 同一篇文章里的图**风格必须统一**。要么都用 mermaid，要么都用 B 档手绘风格，不要三档混着来。

### 7.6 证据纪律

- 图里的**每一个数字、名称、关系都必须来自正文或可核验来源**，不得让模型补全缺失信息。
- 本项目已有先例：一张封面图里出现过数据源中并不存在的列名，是模型自己编的。**信息图出图后要逐项核对图内文字与数据源**，不要只看好不好看。
- 图注如果引用第三方数据，按第 3 节的要求标明来源。

## 8. 交付前自查清单

结构与格式：

- [ ] 层级完整，一级标题下没有直接跳到三级
- [ ] 中英之间、中文与数字之间的空格风格全文统一
- [ ] 并列词用顿号，末项用「和」
- [ ] 中文标点全角，时间用半角冒号（`8:00`）
- [ ] 省略号用 `⋯⋯`，无 `...`，无 `。。。`
- [ ] 没有感叹号连用
- [ ] 数值半角，四位以上加千分号
- [ ] frontmatter `status: draft`

文字：

- [ ] 没有超过 40 字的句子
- [ ] 没有双重否定，没有堆叠的被动语态
- [ ] 每段不超过七行，最好不超过四行，段首是中心句
- [ ] 引用第三方内容已标明出处
- [ ] 已跑 `humanizer-zh` 清一遍 AI 腔（推荐）

图例：

- [ ] 每个关系密集段都过了一遍 7.2 的判断逻辑
- [ ] 每张图紧跟它服务的段落，图下有解读
- [ ] 没有孤立悬挂、正文无指向的图
- [ ] 图里的数据都能在正文或来源里核到
- [ ] 全篇图风格统一，图总数不超过 5
