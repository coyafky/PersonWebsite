# 工作日志 → 博客日记 · 实施计划

> 建立于 2026-09-17。来源：Coya 要求「把每天的工作日志整理好，发布到博客；周记内容拆分成日记，不做周记了」。
> 执行原则：**先走一遍全部步骤写清，再逐步按计划执行**（Coya 原话「先每一步先走一遍，都写上，然后再每一步有规划的执行」）。

---

## 0. 目标与范围

**目标**：把日常工作记录做成博客上一个可浏览的**日记**栏目，一天一篇。

**范围**：
- ✅ 新增内容类型 `diary`（一天一篇，文件名 `YYYY-MM-DD`）
- ✅ 数据来自三个源头（见 §2），共可覆盖 **71 天**（2026-06-01 → 2026-09-17）
- ✅ 敏感信息脱敏（见 §5）
- ❌ 不改动 `content/weekly/`（周记保留原样，只是不再是主要出口）
- ❌ 不新增周记

**产出**：`content/diary/<YYYY-MM-DD>.md` ×N + 站点 `/diary` 列表与详情页

## 3. 技术落点（已探明）

现有架构是「schema → reader → 路由 → 导航」四件套：

```
lib/content/schemas.ts      加 diarySchema + 注册进 kind map
lib/content/reader.ts       加 getDiaryEntries() / getDiaryEntryBySlug()
app/(site)/diary/page.tsx         列表页（分页，仿 blog）
app/(site)/diary/[slug]/page.tsx  详情页（仿 blog）
components/site-nav.tsx     加「日记」导航项
```

可复用组件：`CollectionList` / `EntryCardBlog` / `Pagination`。

## 4. 执行步骤（每步含验收）

### Step 1 · 内容模型落地（最小可跑通）
- 加 `diarySchema`：`kind: "diary"`，必填 `date` / `summary` / `tags` / `lang`，可选 `updated` / `mood` / `source`
- 加 reader 读函数 + 类型
- 加 `/diary` 列表页与 `[slug]` 详情页
- 导航加「日记」
- **验收**：塞 1 篇样例 → `npm run build` 通过 → 产物 `/diary/<date>.html` 存在

### Step 2 · 脱敏规则固化为脚本
- 写 `scripts/diary-sanitize.mjs`：扫描 + 报告命中（不自动改，避免误伤）
- 规则见 §5
- **验收**：对 13 篇现有日志跑出命中报告，逐条可解释

### Step 3 · 生成日记（源 A：13 篇现有日志）
- 从 `content/inbox/logs/` 转写为 `content/diary/`，应用脱敏
- **验收**：13 篇落盘，脱敏清单逐条核对，`build` 通过

### Step 4 · 从周记拆天（源 B：56 条时间轴）
- 抽取每篇周记的 Time Log → 每天一条日记
- 周级正文（进展/思考）按时间轴指向归入对应天
- 与 Step 3 已生成的日期**合并去重**（日志优先，周记补充）
- 标注 `source: weekly`（重建，非当日实记）
- **验收**：日期无重复、无覆盖；重建条目带来源标注

### Step 5 · 从记忆笔记补（源 C：13 天仅记忆）
- 只补「有实质工作内容」的天
- 标注 `source: memory`
- **验收**：仅记忆的 13 天逐天判定「补 / 不补」，不补的写明原因

### Step 6 · 全量校验与上线
- 敏感词全量复扫（供应商/报价/凭证/路径/内部 ID）
- `npm run build` + 生产站抽查
- **验收**：脱敏 0 残留；日记页 HTTP 200

## 5. 脱敏规则（Step 2 的依据）

**为什么必须做**：GitHub 仓库是 **public**（已核实 `coyafky/PersonWebsite`，visibility=public）。且 Coya 本人已明确过口径——供应商名属内部信息不得对外展示（2026-09-17 官网修正时的决策）。

| 类别 | 处理 | 例 |
|---|---|---|
| **供应商名** | ❌ 移除/泛化 | 宝凡、普朗克、鼎仕力、百粤、横泓、添驭、CMST、BSKT、AMXT、昆仑、TEI Racing |
| **报价/价格数字** | ❌ 移除 | 9480/9980/10980… |
| **内部飞书 ID** | ❌ 移除 | `tbl*`、`Q6VQbuL...`、`cli_*` |
| **本机绝对路径** | ⚠️ 泛化 | `/Users/fkycoya/...` → `~/...` 或省略 |
| **cron / job id** | ⚠️ 泛化 | `fa51b411` → 「每日计划任务」 |
| **客户/门店个人信息** | ❌ 移除 | 具体客户名、联系方式 |

| **技术方法/踩坑** | ✅ 保留 | Skill 设计、验证方法、工程决策 |

## 6. 诚实性纪律

1. **不编造**：某天无来源就**不生成**，不靠推测补齐
2. **标来源**：重建的日记（来自周记/记忆）带 `source` 字段，可追溯
3. **薄就是薄**：周记一天只有一行，那条日记就写一行 —— 不注水
4. **区分「谁的工作」**：记忆笔记里 Alma 自己的工作（如技能维护）与 Coya 的业务工作分开表述
